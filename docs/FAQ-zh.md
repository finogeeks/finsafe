# FinShield 常见问题

[English](FAQ.md) · [返回首页](../README-zh.md)

## FinShield 和 FinSafe 是什么关系？

FinShield 是 FinSafe 的新产品名称，中文名为“智能体安全盾”，简称“智安盾”。现有 `finsafe` 命令、配置路径、部分发行文件名和仓库地址继续保留。旧案例中的 FinSafe 名称不是另一个产品。

## Windows 必须运行安装命令吗？

不需要。取得匹配版本的 EXE 后，双击按向导安装。之后从桌面悬浮控件开始安全准备，选择图标启动受支持的智能体；网页控制台辅助确认权限和查记录。[Windows 使用指南](WINDOWS-GUIDE-zh.md)。

## 为什么下载页只有旧版本？

产品代码合并、测试包交付和公开发行是不同步骤。截至 2026-10-29，公开 Releases 最新为 `v0.9.47`，新版桌面 EXE 尚未上架。本文按当前产品流程整理，不表示历史下载包具备所有新功能。以实际交付版本和对应发行说明为准。

## 三个平台体验相同吗？

Windows 提供 EXE，以桌面悬浮控件作为日常入口，本机网页控制台辅助配置和查记录；当前集成 WorkBuddy 和 DSH CLI。macOS、Linux 主要提供命令行入口。macOS 当前发布目标为 Apple 芯片，Intel 新包暂缓；Linux 当前发布目标为 x86_64。隔离机制、应用兼容与内容检查能力随平台和版本变化。

## 装上以后，所有智能体都会自动受到保护吗？

不会。需要完成授权，并通过 FinShield 的受支持入口启动。直接从原厂快捷方式另起的程序、未接入的应用和绕开检查路径的通信，不能默认认为已受保护。已运行应用的界面被打开，也不能单独证明其启动身份和权限。

## 开启 Full Access，会绕过 FinShield 吗？

Full Access 是智能体自身的权限或审批模式。对于确实处于 FinShield 受控执行环境内的进程，该选项不会自行解除操作系统施加的限制。实际结果仍取决于启动身份、有效策略和接入方式，不能只凭界面中的模式名称判断。

## 它能保证模型不犯错、所有攻击都失败吗？

不能。FinShield 约束已接入的执行和数据路径，降低危险操作造成影响的风险。它不保证模型判断正确，也不代表每个系统接口、协议或应用版本均已覆盖。案例只证明对应测试条件下的结果。

## 窗口风暴案例是不是所有 Windows 应用都适用？

不是。案例注明了版本、DSH 模式和桌面配置。私有桌面可以把测试窗口与用户桌面分离；WorkBuddy 等 GUI 应用的交互兼容路径可能不同。保护组桌面没有干扰，也不等于所有窗口创建调用都被拒绝。

## 敏感信息检测到就一定阻止发送吗？

Windows 默认“记录”会告警并继续发送。选择“询问”后，已命中的请求需要单次批准；选择“阻止”后，已命中的请求会被拒绝。未完成检查、无法解读或不支持的内容可能按其他规则继续转发。检测不保证识别全部敏感信息。

macOS／Linux 的 Privacy Guard 使用另一套平台工作流，不应直接套用 Windows 的模式和覆盖范围。

## 本地留存意味着数据不会发送给模型吗？

不是。本地留存保存的是已采集请求、回复和处理结果的本机加密记录。获准的请求仍发往你配置的模型服务。请分别确认文件范围、网络目的地、内容检查与留存设置。

## 智能体无法访问正常工作文件怎么办？

先确认它是否位于已授权的可读写工作区，参考目录是否配置为只读，路径是否存在。需要调整范围时，通过安全设置修改并重新授权，再重新验证实际任务。不要为了消除一条报错而把整个用户目录设为可读写。

## 如何反馈问题

在 [GitHub Issues](https://github.com/finogeeks/finsafe/issues/new/choose) 提交：

- FinShield 版本、操作系统和 CPU 架构。
- Agent 名称与版本，以及从哪个入口启动。
- 操作步骤、预期结果、实际结果和相关错误文字。
- 与问题相关的配置范围和经过脱敏的截图或日志。

请勿提交真实客户资料、密钥、会话令牌或完整敏感对话。敏感安全问题请通过已有 Finogeeks 支持渠道私下反馈。
