WorkBuddy AI 工具安全防护

大模型提出工具请求，真正触碰文件、网络和其他系统的是员工电脑上的 WorkBuddy。

FinSAFE 保护的是本机执行路径 官方 LLM 通道保持正常。试用重点是：当前任务目录能改，工作区外的乱写会被拦住。

装上 FinSAFE 之后，客户能看见什么

不要打开已有项目，也不要把工作区选成桌面或「文档」。在 WorkBuddy 里新建任务，用默认工作区（用户目录下的 WorkBuddy 文件夹）。下面四件事，是销售可以当场对照的。

1. 误改「文档」里的文件

装之前让助手把内容写到「文档」，文件会出现。
装之后当前任务目录里照常能写；写到「文档」会失败。

2. 点了 Full Access

装之前原厂沙箱基本不再约束，命令按登录用户权限执行。
装之后Full Access 跳过的是 WorkBuddy 自己的沙箱，跳不过 FinSAFE。再写「文档」仍应失败。

3. 模型手滑，或网页里藏了指令

装之前模型真去改桌面、清文件时，没有外层拦住。
装之后越界写入仍按第 1 条被挡；正常改当前任务不受影响。

4. 关掉 WorkBuddy 之后

装之前终端、Python、git 有时还会留着。
装之后从托盘退出，这些后续进程应被一起收掉。

黄色：正常入口有门卫

LLM 使用 WorkBuddy 的正常工具时，FinSAFE 可以检查、阻止并记录操作。它能有效降低模型误判、提示词注入和常见越权风险，但特殊的内部路径仍可能绕开这个入口。

绿色：门本身已经上锁

限制由 Windows 或不可绕过的统一出口强制执行。程序即使更换工具或执行方式，只要不符合策略，系统仍会拒绝，保证强度更高。

FinSAFE 为客户带来的价值

高风险工具进入外层边界 shell、PowerShell、Python、git 和本地 MCP 不再只依赖 WorkBuddy 自身判断。
Full Access 不等于完全放开 用户可以跳过原厂沙箱，但本地工具仍不能跳过 FinSAFE。
策略与审计更加统一 文件写入、工具启动、网络目的地和拦截结果可以集中记录。

FinSAFE 重点保护 LLM 能触发的本机工具路径，不是把整个 WorkBuddy 装进沙箱。试用默认仍允许读取文件，也不锁外网——读机密、锁网是下一步，不要拿来当本周演示。
